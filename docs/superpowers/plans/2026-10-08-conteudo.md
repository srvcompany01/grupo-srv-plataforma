# Pipeline de conteúdo (Social & Conteúdo) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Criar, versionar e enviar posts para aprovação do cliente dentro da plataforma, com quadro por etapa, calendário editorial e agrupamento por cliente.

**Architecture:** O post é uma tarefa da lista de conteúdo; formato, versões, mídias e respostas do cliente ficam em tabelas ligadas à tarefa (RLS pelo acesso à tarefa). O link público do cliente roda só no servidor, com o cliente admin do Supabase, filtrando por `clients.approval_token`.

**Tech Stack:** Next.js (versão nova, ler `node_modules/next/dist/docs/` antes de criar rotas), Supabase/Postgres com RLS, R2 (URL assinada), Vitest com pglite para testes de banco, Tailwind v4.

**Spec:** `docs/superpowers/specs/2026-10-08-conteudo-design.md`

## Global Constraints
- Formatos: `feed`, `reels`, `stories`, `tiktok`. Aprovação: `rascunho`, `aguardando`, `aprovado`, `ajuste`.
- Versão respondida é imutável; editar cria a versão N+1 e volta para `aguardando`.
- O cliente nunca tem acesso direto às tabelas: só o servidor lê pelo `approval_token`.
- Mídia: reaproveitar `src/dominio/midias.ts` (tipos e limites do módulo antigo) e o R2 de `src/infra/r2.ts`.
- Migration só adiciona; o usuário a roda no SQL Editor de produção antes do deploy (ver memória `migrations-producao`). Código deve degradar sem a tabela.
- Textos em português; sem `confirm()` nativo (usar `useConfirmar`).

## Review Focus
1. Token de outro cliente (ou inexistente) nunca enxerga post: 404, sem vazar que o post existe.
2. Responder duas vezes a mesma versão é rejeitado (a segunda não sobrescreve a primeira).
3. Editar depois da resposta cria a versão N+1 e não altera a versão antiga nem sua resposta.
4. Registrar mídia com chave R2 que não pertence à tarefa, tipo inválido ou tamanho acima do limite é rejeitado.
5. Post em `rascunho`, arquivado ou de tarefa arquivada nunca aparece no link do cliente.
